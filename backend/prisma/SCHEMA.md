# SAIS database schema

Backend 4 establishes the normalized PostgreSQL foundation for the School Administration Information System.

## Design rules

- Every tenant-owned aggregate carries `tenantId` or is reached through a tenant-owned parent.
- IDs use PostgreSQL UUIDs generated by Prisma.
- Tenant-scoped natural identifiers use composite unique constraints.
- Historical records are retained; destructive cascade behavior is limited to dependent records.
- Authentication is intentionally not implemented here. `UserSession` stores only token hashes and expiry metadata for the later identity-security phase.
- All timestamps are UTC `DateTime`; date-only attendance uses PostgreSQL `date`.

## Domain groups

- Platform: `Tenant`, `School`, `Campus`, `TenantSetting`
- Identity and RBAC: `User`, `Role`, `Permission`, `UserRole`, `RolePermission`, `UserDevice`, `UserSession`
- Academics: `AcademicYear`, `AcademicTerm`, `Student`, `Guardian`, `StudentGuardian`, `Staff`, `Enrollment`
- Operations: `AttendanceRecord`, `Notification`, `AuditLog`

The schema intentionally leaves future module tables to later backend phases. API behavior, authentication flows, authorization middleware, and business services are not part of Backend 4.

## Migration workflow

```bash
npm run db:check -w backend
npm run db:migrate -w backend
npm run db:migrate:status -w backend
npm run db:generate -w backend
npm run db:seed -w backend
npm run db:studio -w backend
```

Run `db:reset` only against disposable development databases. Never reset production data. Production deploys should use `db:migrate:deploy` after reviewing the migration SQL.
